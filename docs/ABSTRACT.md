# Abstract

LLM serving models often represent service rate as a smooth function of useful batch size, yet runtime execution regimes can introduce sharp changes. We study SGLang decode on a single NVIDIA RTX 4070 using Qwen2.5-0.5B-Instruct with BF16 and FlashInfer. A controlled experiment holds useful batch size at eight while comparing CUDA Graph replay with forced eager decode. Separate unprofiled measurements across three server restarts per arm estimate serving performance; three Nsight Systems traces per arm characterize execution structure. Graph replay reduces mean decode interval from 10.114 to 3.117 ms, a 3.244× ratio, while observed GPU-work union changes only from 362.619 to 352.906 µs per useful decode-token equivalent. Eager exhibits 29.125 versus 1.750 individual runtime kernel launches per token and 1,158.017 versus 40.955 µs/token of inter-kernel gaps. Kernel-name sequence similarity is 98.442%. Event correlation, synchronization analysis, and a smaller output256 confirmation strongly support host/runtime launch and orchestration structure as the dominant mechanism associated with the larger eager execution gaps. Asymmetric profiler perturbation, completeness warnings, and unresolved dependency attribution preclude exact causal decomposition. The evidence supports a regime-aware service abstraction, μ(B,m), for empirical service curves, batching decisions, and queueing models. The conclusion is Level-2 strong mechanism evidence, not Level-3 causal attribution.
